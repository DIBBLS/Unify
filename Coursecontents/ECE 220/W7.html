Week 7 of 12 Program Planning / SDLC

Before writing a single line of code, professional developers follow a structured process called the Software Development Life Cycle (SDLC). The 2024/2025 exam asked directly for the 6 SDLC steps (Q1b, 5 marks). Know them in order.

Topic 7.1
The 6 Steps of the SDLC
Step 1 — Feasibility Study

Inspect how viable and achievable the project is. Check availability of requirements, resources, and personnel. Is the project worth doing?

Step 2 — System Design

Create a systematic design/blueprint after the feasibility study. This includes data structures, interfaces, and algorithms before any code is written.

Step 3 — Implementation (Coding)

The actual coding phase. Developers write code based on the design document. This is where Python programs are written.

Step 4 — Testing

Test the code to find errors/bugs. Three types: Unit Testing (test individual components), Integration Testing (test components working together), User-Interface Testing (test from the user's perspective).

Step 5 — Deployment

Release the code to the client. The developer must ensure the code is flexible, documented, and ready for use in the real environment.

Step 6 — Maintenance

Annual or periodic checks on the program to protect, maintain, and improve it. Bug fixes, updates, and security patches.

Exam answer — write this verbatim
The SDLC consists of 6 steps: (1) Feasibility Study — assess viability; (2) System Design — create a blueprint; (3) Implementation — write the code; (4) Testing — find and fix bugs; (5) Deployment — release to client; (6) Maintenance — ongoing support and improvement.
Topic 7.2
Pseudocode

Pseudocode is plain-English description of an algorithm — not actual Python syntax, but structured enough to be converted to code easily.

Example — Find the larger of two numbers
START
  INPUT number_a
  INPUT number_b
  IF number_a > number_b THEN
    OUTPUT "number_a is larger"
  ELSE
    OUTPUT "number_b is larger"
END
Common mistake
Listing only 4 or 5 SDLC steps — the full list is 6. Testing (step 4) is the one most students forget to split into unit/integration/UI. Also: confusing Deployment (release to client) with Maintenance (ongoing support after release).
